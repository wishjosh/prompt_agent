# 작업 흐름

이 폴더는 검증된 프롬프트 패키지가 아니라, 프롬프트를 만들고 고치는 작업대다.

## 기본 순서

1. `principles/`에서 원칙을 확인한다.
2. `guides/`에서 작성·실행 메모를 확인한다.
3. `prompts/`에서 실제로 쓸 프롬프트를 고른다.
4. NotebookLM에서 수동 실행한다.
5. 결과와 실패를 `tests/runs/`에 기록한다.
6. 반복 실패가 보이면 프롬프트 파일을 직접 고친다.

## 현재 원칙

- 프롬프트 하나는 파일 하나로 관리한다.
- 실행자가 확인할 내용은 `사용 전 메모`에 두고, 모델에게 먹일 내용은 `복사해서 실행할 프롬프트` 아래에 둔다.
- 검증 전에는 `library`, `package`, `core`, `adapter`, `build`를 쓰지 않는다.
- 오래된 실험과 구조는 삭제하지 않고 `archive/`에 보존한다.

## 상태 표현

- `draft`: 실행 가능한 초안.
- `working draft`: 1회 이상 쓴 흔적은 있으나 아직 표준은 아님.
- `tested`: 여러 입력에서 실행해 실패 양상을 알고 있음.
- `stable`: 반복 사용 중인 표준 프롬프트.
