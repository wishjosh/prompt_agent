## [2026-05-23] 영상 해체 프롬프트 신설 및 단일 심층 해체 세분화 합의

**1. RES-002-G (영상 단일 소스 심층 해체) v1.0 초안 작성**
- 기존 RES-002가 학술 논문(IMRaD) 구조를 전제로 한 점을 인식하고, 영상 매체의 휘발 문제에 대응하는 별도 프롬프트 신설.
- 7개 출력 섹션: (1) 화자/맥락 메타 (2) 뼈대 재구성 (3) Core 논증 — 다중 화자 분리 (4) Secondary 스파크 (5) 글로사리 (6) 실용 아티팩트 (7) 무근거 주장 / 재시청 대상.
- **글로사리 ⚠️ 정책**: 화자가 정의 안 준 용어는 일반 지식으로 보완하되 ⚠️ + "추가검토" 마크 강제 → 환각 금지 원칙과 휘발 방지의 균형.
- **다중 화자 분리 강제**: 인터뷰·대담·패널은 화자별로 Core 블록 분리 출력.
- **타임스탬프 인용**: NotebookLM의 영상 인용 마커에 타임스탬프 병기 강제 → 재시청 비용 최소화.
- **자의적 재구성 금지**: 뼈대 재구성 시 화자의 메타발화(전환 신호)를 근거로만 단락 분할 → 발화 인용을 출력에 병기.
- **실용 아티팩트 약한 강제**: 영상에 없을 수도 있으므로 "없음" 명시 허용. 빈 섹션도 정보로 취급.

**2. 단일 심층 해체(RES-002) 소스 유형별 세분화 방향 합의**
- 향후 sub-ID 후보 7종 확정: A(논문) / B(단행본·하이브리드 보류) / C(보고서) / D1(법령-실행 리스크) / D2(법령-입법) / E(기사) / G(영상-작성 완료).
- **법령은 2종 분기**: 정책 실행 시 법적 리스크 검토 vs 입법(제정·개정) 연구 — 같은 조문도 시선이 완전히 다름.
- **보고서는 시점 메타데이터 강제 예정**: 발간일 − 6~12개월 시점의 정권 사이클(교체기/시작기/안정기/레임덕기) 또는 경기·예산 사이클 식별을 출력 첫 섹션에 포함.
- **단행본은 워크플로 합의 보류**: 오프라인 1차 독서 → 연구자 종합 메모 → AI 해체의 하이브리드 입력 형태가 미정.

**3. 품질 필터링 게이트(RES-000-D) 제안 폐기**
- 수집-해체 사이의 횡단 품질 필터 신설을 검토했으나 "옥상옥" 판단으로 폐기.
- `memory/feedback_no_quality_gate.md` 신설하여 향후 유사 제안 차단.

**4. RES-002 → RES-002-A 재명명 (v1.1 → v1.2)**
- 기존 RES-002(`RES-002_single_source_deep_dive.md`)를 `RES-002-A_paper_deep_dive.md`로 `git mv` 처리하여 git 이력 보존.
- 제목 및 NotebookLM 실행 지침에 "학술 논문" 명시. "(논문, 보고서, 기사 등)"으로 광범위하게 적혀 있던 적용 대상을 학술 논문(IMRaD) 단일 유형으로 좁힘.
- 영상은 RES-002-G로, 그 외(보고서·법령·기사·단행본 등)는 향후 추가 예정임을 지침에 안내.
- 카탈로그 행 ID·파일경로·버전 동시 갱신.

**5. catalog.md 업데이트**

## [2026-05-18] 대규모 문헌 스캐닝을 위한 프롬프트 최적화 (v1.1 -> v1.3)

**1. 다중 소스 스캐닝 프롬프트 점진적 고도화**
- **v1.2 (누락 방지 및 세분화)**: 277개의 방대한 소스를 단 3개의 군집으로 묶고 나머지 소스를 누락시키는 현상 발견. 군집을 최소 5~6개로 세분화하도록 강제하고, 군집별 할당된 총 개수 표기 및 나머지 모든 소스 제목을 나열하도록 지시하여 데이터 누락 방지.
- **v1.3 (가독성과 신뢰성의 균형)**: 수백 개의 소스를 쉼표로 나열할 경우 가독성이 심각하게 저하되고 출력 토큰 한계에 부딪히는 문제 발생. 무리한 전체 나열 대신, 군집별 총 개수 명시는 유지하되 세부 목록은 '불릿(Bullet) 기호 + 인용 마커' 형태로 7~10개 내외의 대표 소스만 깔끔하게 출력하도록 출력 형식 타협.

**2. 프롬프트 테스트 환경 구축**
- 실제 NotebookLM 실행 결과물과 출력 스냅샷을 체계적으로 보관하기 위해 프로젝트 루트에 `test_results/` 디렉토리 신설.
- `README.md`를 통해 `[날짜]_[프롬프트명]_[간략한특징].md`의 네이밍 컨벤션을 수립하고 테스트 인덱스(Log) 관리 시작.

- **조치**: 파이프라인 순서에 맞게 파일명 및 카탈로그 ID를 재정렬함.
  - 탐색 프롬프트 3종: `RES-000-A1`, `A2`, `A3` 로 변경

## [2026-05-16] 수집/해체 국면 프롬프트 7종 개발 및 NotebookLM 전면 리팩토링

**1. 신규 프롬프트 초안(v1.0) 7종 일괄 설계**
- 지식 체계(Knowledge System)의 레벨 2(수집) 및 레벨 3(해체) 원칙을 코드로 구현하는 7개의 핵심 프롬프트 초안 작성.
- **수집 국면 (Collection Phase)**
  - `RES-000-A` (모드별 탐색 전략): 초기에는 1개의 파일로 구상했으나, 모드별로 파고드는 렌즈가 완전히 다르다는 점을 인지하고 3개로 분리.
    - `RES-000-A1` (사회 인식 탐색): 대중 트렌드 및 편견 발굴. (논문/법안 배제)
    - `RES-000-A2` (학술 이론 탐색): 이론적 렌즈(Framework) 및 거장 발굴.
    - `RES-000-A3` (정책 현실 탐색): 관련 법령, 부처, 이해관계자 발굴.
  - `RES-000-B` (모드별 타겟팅 필터): 쏟아지는 소스 중 특정 모드에 맞는 소스만 노이즈 제거(Facilitator). 타 모드 소스 잔류 강제로 세렌디피티 보존.
  - `RES-000-C` (교차 모드 입체 종합): 단편적 서사를 융합하여 단일 렌즈의 사각지대를 보완하고 입체적 해결책 제안 (초기 기획 당시엔 '간극 분석'이었으나 작위성을 배제하기 위해 입체 종합으로 개편됨).
- **해체 국면 (Deconstruction Phase)**
  - `RES-001` (다중 소스 스캐닝): 다량 문헌의 뼈대에 따른 군집화 및 주변부 소스 기록.
  - `RES-002` (단일 소스 심층 해체): 엑스레이 구조화(저자 프레임 투명 노출) 및 핵심(Core)과 주변부(Secondary) 분리 출력. 일반 요약과 차별화.
- **자산화 국면 (Assetization Phase)**
  - `RES-003` (논리적 결합): 연구자의 인용 의도를 입력받아, 원작자의 의도와 팩트체크 후 논리적 비약(체리피킹)을 경고하는 프롬프트 (Critical Friend 모드).
  - `RES-004` (창조적 스파크): 영감을 준 소스와 거친 아이디어를 결합하여 가설로 구조화하고, 현재 증명할 수 없는 Missing Links를 찌르는 프롬프트 (CF 모드).

**2. NotebookLM 최적화 전면 리팩토링 (v1.0 -> v1.1)**
- **배경**: 모든 프롬프트를 구글 NotebookLM 기반으로 실행하기로 결정.
- **주요 변경 사항**:
  - `[NotebookLM 실행 지침]` 상단 추가: 프롬프트 실행 전 어떤 소스(Seed 문서, 다중/단일 소스)를 체크해야 하는지 명시.
  - **인용 마커 강제**: 출력 템플릿의 모든 주장 뒤에 `[인용 마커]` 플레이스홀더를 추가하여, NotebookLM이 `[1]`, `[2]` 형태로 원문을 강제 인용하도록 조치. (기계적 마찰 최소화)
  - **환각 원천 차단**: "선택된/업로드된 소스에 기반해서만 답하라"는 제약 조건 강화. (특히 탐색 프롬프트 C1~C3는 Seed 문서 기반 작동 방식으로 전환)
