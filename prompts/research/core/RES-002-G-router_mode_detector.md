# 영상 모드 판별기 (Video Mode Router) — 코어 (v1.0)

> **먼저 물어라**: 본격 해체 전, 이 영상에 어떤 처리 깊이가 맞는지 판단하는 비용을 낮춘다.
> **코어 파일 (환경 중립)**: 어댑터와 함께 사용. 짝 어댑터: `adapters/RES-002-G-router.{환경}.md`
> **파이프라인**: 이 판별기(1단계) → 추천 모드의 `RES-002-G-{deep|brief|recipe}`(2단계)

## [필수] 메타 헤더

| 항목 | 값 |
|------|-----|
| ID | RES-002-G-router |
| 층 | Composite (영상 해체 파이프라인 1단계) |
| 매체 | 영상 |
| AI 역할 | Facilitator |
| 도메인 | research |
| 버전 | v1.0 |

## [필수] 목표 행위

영상 1편의 길이·밀도·구조 신호를 근거로 `deep` / `brief` / `recipe` 중 처리 모드를 추천하고 이유를 1~2줄로 제시한다.

## [필수] AI 역할

- **모드**: Facilitator. 모드는 **추천만** 하고 강제하지 않는다. 최종 선택은 연구자.

## 모드 기준 (간략)

- `deep` — 30분 이상이거나 밀도 높은 논증·사례가 다수
- `brief` — 15분 이내, 정보 전달·소식 알림 위주
- `recipe` — 단계별 실행·시연이 본체

## 절차

1. **신호 수집**: 길이, 화자의 메타발화 패턴, 시각 자료·시연 여부, 논증 밀도
2. **추천**: 세 모드 중 하나 + 이유 1~2줄. 신호가 경합하면 차순위도 병기.

## 출력 형식

```markdown
## 영상 모드 판별 결과

- **추천 모드**: `deep` / `brief` / `recipe`
- **추천 이유**: [길이·밀도·구조 신호 근거 1~2줄] [출처+시점]
- **차순위** (경합 시): `[모드]` — [이유 한 줄]
- **다음 단계**: 추천 모드를 확인하셨으면 `RES-002-G-[모드]` 프롬프트로 본 해체를 진행하세요.
```

## [필수] 제약조건

1. **판정 강제 금지**: 추천만 한다. 연구자가 다른 모드를 선택할 수 있다.
2. **환각 금지**: 대상 영상 밖 정보로 판단하지 마라.
3. **출처 표기**: 판단 근거가 된 지점에 `[출처+시점]` 토큰을 부착하라. (실제 형식은 어댑터)
