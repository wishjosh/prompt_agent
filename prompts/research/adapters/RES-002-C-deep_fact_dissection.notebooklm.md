# RES-002-C-deep × NotebookLM 어댑터

> **어댑터 파일**: 코어 [`RES-002-C-deep_fact_dissection.md`](../core/RES-002-C-deep_fact_dissection.md)와 함께 사용한다.
> **조립 순서**: 코어 본문 → `---` → 본 어댑터 본문 순으로 붙여넣고, 맨 아래 입력란을 채워 실행.

| 항목 | 값 |
|------|-----|
| 짝 코어 | RES-002-C-deep |
| 환경 | NotebookLM |
| 버전 | v1.0 |

## 1. 실행 전 준비

1. 심화할 **보고서 1편만** 소스 체크박스에서 '선택'하세요.
2. **⚠️ Studio는 보고서마다 별개 파일을 생성해 1차 스캔→deep 자동 연계가 안 된다.** 따라서 1차 스캔(`RES-002-C-scan`)의 핵심 맥락(발행주체·시점·기준연도·전역 한계·구조 지도)을 deep **프롬프트 본문에 직접 박아넣고**, 그 아래 입력란에 **심화할 장/절**을 적어라. 같은 보고서를 5부 순회할 땐 고정 맥락은 그대로 두고 심화 범위 한 줄만 교체하면 된다. 범위를 좁힐수록 입력 한계 안에서 더 깊게 해체된다.
3. 코어 + 본 어댑터(+ 박아넣은 스캔 맥락)를 함께 복사해 **NotebookLM Studio의 '보고서 기능'에 붙여넣어 실행**하세요. (단일 소스 해체는 채팅창보다 Studio 보고서 기능이 결과가 안정적 — 2026-05 실사용 확인.)

## 2. 출처 플레이스홀더 치환 규칙 (횡단)

| 코어 토큰 | NotebookLM 출력 형식 | 예시 |
|---|---|---|
| `[출처]` | 인용 마커 (플랫폼 자동) — 텍스트로 직접 쓰지 말 것 | `[1]` |
| `[위치]` | 페이지·장 위치를 본문에 직접 표기 | `(p.23)` / `(3장 2절)` |
| `[출처+위치]` | 자동 인용 + 본문 페이지 표기 | `…명시 (p.23)` |

Secondary Fragment의 `[위치/페이지]` 칸에는 `(p.XX)` 또는 `(N장 M절)`을 직접 적어라. **모든** 항목 끝의 토큰을 빈 채로 두지 마라.

## 3. 환경 특화 제약

- **선택 소스 한정**: '선택'된 해당 보고서 범위 내에서만 답하라. 다른 소스·외부 지식 금지. (단, 글로사리 ⚠️ 보완 정의는 코어 제약 1의 예외 규정을 따른다.)
- **범위 한정**: 입력란에 지정된 장/절을 벗어난 부분까지 해체하지 마라. 지정 범위 밖은 1차 스캔 지도에만 남긴다.

## 4. 입력 전달

아래를 복사해 괄호를 채워 코어·어댑터 뒤에 이어 실행하세요.

- **(권장) 1차 스캔 결과**: [RES-002-C-scan 출력 붙여넣기]
- **(필수) 심화 범위**: [예: "3장 산업구조 변화 전체", "5장 2절 오픈스페이스 지표만"]
- **(선택) 부연 설명**: [예: "데이터 변곡점 위주로 Core를 두껍게", "각주·민원 기록을 특히 꼼꼼히"]
- **(선택) 연구 맥락**: [예: "노후 도시공원 재생 사례 누적 정리 중"]
- **(선택) 특별 주목 지점**: [예: "특정 행정구역 경계 변경 이유만 별도 정리"]
