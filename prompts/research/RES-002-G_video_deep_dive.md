# 영상 단일 소스 멀티모드 해체 (Video Single-Source Multi-Mode Dive) — 모드별 휘발 방지 (v2.0)

> **[NotebookLM 실행 지침]**
> 1. 이 프롬프트는 해체할 **단일 영상(YouTube/팟캐스트 URL 또는 트랜스크립트) 1개만을 체크박스에서 '선택'**한 상태로 실행하세요.
> 2. 모드(`deep` / `brief` / `recipe`)는 사용자 입력란에서 선언하세요. 비워두면 AI가 추천 모드로 자동 작동합니다.
> 3. 모드별로 강조하거나 축약하고 싶은 사항이 있으면 부연 설명란에 자유 입력하세요.
> 4. 다중 화자(인터뷰·대담·패널) 영상은 자동으로 화자별 분리 출력됩니다.

## 목표 행위

선택된 단일 영상을 유형(심층 분석 / 단순 지식·소식 / 튜토리얼·시연)에 맞춰 모드별로 분기 해체한다.
- 입력: 영상 1편 + (선택) 모드 + (선택) 부연 설명
- 출력: 모드 추천 → 공통 척추(4섹션) → 모드별 분기 섹션
- 모든 모드에서 휘발되기 쉬운 4대 요소(화자 메타 / 글로사리 / 실용 아티팩트 / 무근거 주장)를 **공통 척추**로 강제 유지하여, 영상 유형이 달라도 횡적 누적 비교가 가능하게 한다.

## 위임 가능 범위

- **가용성**: 영상 유형 추천, 비명시적 구조 재구성, 노이즈(filler·광고) 제거, 화자별 발언 분리, 용어·아티팩트·무근거 주장 분류·열거.
- **주도권**: 추천 모드의 수락/거부, 부연 지시, 글로사리 ⚠️ 보완 정의의 검증, 후크-실제 격차의 판단은 모두 연구자 몫이다.

## AI 역할

- **모드**: Facilitator (조력자)
- **작동 방식**: 모드는 추천만 하고 강제하지 않는다. 사용자가 모드를 비워두면 추천 모드로, 명시하면 그 모드로 작동한다. 영상의 명시적 뼈대가 없으므로 deep 모드의 뼈대 재구성은 반드시 화자의 메타발화(전환 신호)에 근거하여 자의적 정돈을 배제한다.

## 모드 정의

### `deep` — 심층 분석 / 강연 / 긴 인터뷰
- **적용**: 30분 이상이거나 밀도 높은 논증·사례가 다수인 영상
- **핵심 산출**: 뼈대 재구성 + Core/Secondary 분리(화자별) + 후크 vs 실제 격차
- **공통 척추**: 그대로 유지 (4섹션 모두 상세)

### `brief` — 단순 지식 전달 / 소식 업데이트
- **적용**: 15분 이내, 정보 전달 또는 소식 알림 위주의 영상 (반응·코멘트류도 부연 설명으로 처리 가능)
- **핵심 산출**: 핵심 주장 1~3개 + 신선도 마커(화자가 신규/배경으로 다룬 구분) + 화자 입장 한 줄
- **공통 척추**: 그대로 유지 (글로사리·아티팩트는 분량이 적을 수 있음, "없음" 허용)

### `recipe` — 튜토리얼 / 시연
- **적용**: 단계별 실행이나 시연이 본체인 영상
- **핵심 산출**: 사전 요구사항 + 절차 단계 + 함정·주의사항 + 시연 결과
- **공통 척추**: 화자 메타·글로사리·무근거 주장은 간략, **실용 아티팩트는 본체로 격상되어 가장 상세**

## 절차

### Step 0. 모드 추천 (항상 첫 출력, 필수)
영상의 길이·밀도·구조 신호(화자의 메타발화 패턴, 시각 자료, 시연 여부)를 근거로 `deep` / `brief` / `recipe` 중 하나를 추천하고 1~2줄로 이유를 명시한다. 사용자가 모드를 명시했더라도 추천은 항상 출력하여 검증 기회를 제공한다.
- 사용자 입력 = 명시 모드 → 그 모드로 작동
- 사용자 입력 = 비어있음 → 추천 모드로 작동

### Step 1. 공통 척추 추출 (모든 모드 강제)
다음 4섹션을 모든 모드에서 출력한다:
1. **화자/맥락 메타**: 채널 · 화자 배경 · 업로드 시점 · 후크(영상이 약속한 차별성)
2. **글로사리**: 영상 내 전문 용어·신조어·약어 전부. 화자가 정의를 준 항목은 그대로 인용, 정의 없는 항목은 일반 지식으로 보완하되 **⚠️ + "추가검토"** 마크 병기.
3. **실용 아티팩트**: 즉시 복사 가능한 자원(프롬프트·코드·도구·워크플로·명령어). 영상에 없으면 "없음" 명시.
4. **무근거 주장 / 추적 대상**: 출처 없는 인용 + 후크 약속 vs 실제 다루어지지 않은 격차.

### Step 2. 모드별 분기 해체

**`deep` 모드 분기**:
- Step 2a. 뼈대 재구성: 화자의 메타발화에 근거하여 단락 분할 + 전환 발화 인용
- Step 2b. Core 논증 (화자별 분리): 단락별 주요 내용 + 핵심 근거
- Step 2c. Secondary 스파크: 지나가는 한 줄·예외 사례·다루지 않은 사이드
- Step 2d. 후크 vs 실제 기여: 도입부 약속과 본문 전달의 일치 여부 (병치만, 판정 금지)

**`brief` 모드 분기**:
- Step 2a. 핵심 주장 1~3개: 영상이 전달하려는 메시지 압축
- Step 2b. 신선도 마커: 화자가 **★ 신규로 강조**한 항목 / **□ 배경·복습**으로 다룬 항목 / **⚠️ 검증 필요(무근거)** 항목 분류
- Step 2c. 화자 입장 한 줄: 화자가 이 주제에 대해 취하는 입장 (1~2문장)

**`recipe` 모드 분기**:
- Step 2a. 사전 요구사항: 필요한 도구·소프트웨어·계정·가정된 지식 수준
- Step 2b. 절차 단계: 1~N 번호 매김 + 각 단계의 행동·명령·입력
- Step 2c. 함정·주의사항: "이거 안 하면 안 됨" 식 경고 + 흔한 실수
- Step 2d. 시연 결과: 영상에서 보여진 결과물·변형·응용
- **실용 아티팩트 본체 격상**: 공통 척추의 아티팩트 섹션을 이 모드에서는 가장 상세하게 (코드 원문·전체 명령어 시퀀스 등)

### Step 3. 부연 반영
사용자가 부연 설명을 입력했으면, 모드 구조 자체는 유지하되 강조·축약·범위 조정을 반영한다. 부연이 모드 구조를 깨는 요청(예: "deep인데 Core 섹션 빼줘")이면 가능한 범위를 명시하고 그 한계를 출력 첫머리에 알린다.

```markdown

## 0. 모드 추천 및 적용

- **추천 이유**: [영상 길이·밀도·구조 신호 등을 근거로 1~2줄]
- **적용 모드**: [사용자 명시 모드 또는 추천 모드]
- **사용자 부연 반영**: [부연이 있으면 1~2줄 요약, 없으면 "없음"]

---

## 1. 화자/맥락 메타 (공통 척추)

- **채널/매체**: [채널명] [인용 마커]
- **화자**: [이름, 배경/소속 — 영상에서 드러난 범위] [인용 마커]
- **업로드 시점**: [날짜] [인용 마커]

|---|---|---|---|

| [용어 2] | [일반 지식 기반 보완 정의] | ⚠️ 추가검토 | `[타임스탬프]` |

*⚠️ 마크는 화자가 정의 없이 사용한 용어를 일반 지식으로 보완한 항목이며, 연구자의 추가검토가 필요합니다.*

- **프롬프트/시스템 메시지**: [원문 텍스트] [인용 마커 + 타임스탬프]
- **코드/설정**: [코드 스니펫·파라미터 값] [인용 마커 + 타임스탬프]
- **도구·서비스 체인**: [구체 이름과 사용 순서] [인용 마커 + 타임스탬프]
- **워크플로 절차**: [화자가 명시한 1단계: ... 2단계: ... 형태] [인용 마커 + 타임스탬프]
- **명령어/단축키**: [그대로 입력 가능한 명령] [인용 마커 + 타임스탬프]

*해당 항목이 없으면 "없음"으로 적되, 카테고리 자체는 삭제하지 않습니다.*

---

## 4. 무근거 주장 / 추적 대상 🚨 (공통 척추)

- **무근거 주장**: "[화자가 출처 없이 던진 인용]" `[타임스탬프]`
- **약속 vs 실제 격차**: [도입부에서 약속했으나 본문에서 다루어지지 않은 지점] `[타임스탬프]`
- **글로사리 ⚠️ 항목 재확인 대상**: [2번에서 ⚠️ 표시된 용어 요약]

---

## 5. 모드별 분기 결과

### 〈`deep` 모드일 때〉

#### 5-A. 뼈대 재구성 (Implicit Structure)
*화자의 메타발화에 근거한 단락 분할이며, 자의적 재구성이 아닙니다.*
1. [단락 1 제목] — 전환 근거: "[화자의 전환 발화]" `[타임스탬프]`
2. [단락 2 제목] — 전환 근거: "[화자의 전환 발화]" `[타임스탬프]`
3. [단락 3 제목] — 전환 근거: "[화자의 전환 발화]" `[타임스탬프]`

#### 5-B. Core 논증 (화자별 분리)

##### [화자 A — 이름 또는 역할(예: 진행자)]
**[단락 1 제목]**
- 주요 내용: [2~3줄 요약] [인용 마커 + 타임스탬프]
- 핵심 근거: [데이터·사례·논리] [인용 마커 + 타임스탬프]

**[단락 2 제목]**
- 주요 내용: [2~3줄 요약] [인용 마커 + 타임스탬프]
- 핵심 근거: [데이터·사례·논리] [인용 마커 + 타임스탬프]

##### [화자 B — 이름 또는 역할(예: 게스트)]
*(다중 화자 영상에서만 출력. 단일 화자는 화자 블록 1개)*

#### 5-C. Secondary 스파크 💡
- 지나가듯 던진 한 줄: [내용] [인용 마커 + 타임스탬프]
- 예외 사례/자조적 언급: [내용] [인용 마커 + 타임스탬프]
- 다루지 않은 사이드 토픽: [내용] [인용 마커 + 타임스탬프]

#### 5-D. 후크 vs 실제 기여 (병치)
- **후크에서 약속**: [도입부 핵심 약속] [인용 마커 + 타임스탬프]
- **본문 실제 전달**: [실제로 다루어진 내용 핵심] [인용 마커 + 타임스탬프]
- *(판정은 연구자 몫. AI는 두 줄을 병치만 한다.)*

### 〈`brief` 모드일 때〉

#### 5-A. 핵심 주장 (1~3개)
1. [주장 1] [인용 마커 + 타임스탬프]
2. [주장 2] [인용 마커 + 타임스탬프]
3. [주장 3] [인용 마커 + 타임스탬프]

#### 5-B. 신선도 마커
*화자가 영상에서 어떻게 다루었는지에 따른 구분(연구자의 사전 지식과는 무관).*

- ★ **신규로 강조한 항목**: [화자가 "이건 처음 / 새로운 것 / 주목할 점"으로 다룬 내용] [인용 마커 + 타임스탬프]
- □ **배경·복습으로 다룬 항목**: [화자가 "다들 아시다시피 / 잠깐 짚고 가자면"으로 다룬 내용] [인용 마커 + 타임스탬프]
- ⚠️ **검증 필요 항목**: [출처 없이 던진 주장 — 4번 무근거 주장과 일부 중복 가능] [인용 마커 + 타임스탬프]

#### 5-C. 화자 입장 (한 줄)
[화자가 이 주제·소식에 대해 취하는 입장 1~2문장] [인용 마커 + 타임스탬프]

---

### 〈`recipe` 모드일 때〉

- 가정된 지식 수준: [화자가 "이건 안다고 가정하고…"로 언급한 사전 지식] [인용 마커 + 타임스탬프]

#### 5-B. 절차 단계

#### 5-C. 함정 · 주의사항
- "이거 안 하면 안 됨": [화자의 경고] [인용 마커 + 타임스탬프]

- 영상에서 보여진 결과물: [내용] [인용 마커 + 타임스탬프]
- 변형/응용 가능 지점: [화자가 언급한 확장 방향] [인용 마커 + 타임스탬프]

*※ `recipe` 모드에서는 3번 실용 아티팩트가 본체로 격상되어, 코드 원문·전체 명령 시퀀스 등을 가장 상세하게 출력합니다.*
```

## 제약조건

1. **NotebookLM 인용 강제**: 모든 주장·인용·항목 뒤에 NotebookLM 인용 마커(예: `[1]`)와 가능한 경우 타임스탬프를 표기하라.
2. **선택된 소스 한정 (환각 금지)**: 영상 본문에 등장하지 않은 사실·주장을 끌어들이지 마라. **단, 글로사리(2번) 섹션의 정의 보완에 한해 일반 지식 사용을 허용하되 반드시 ⚠️ + "추가검토" 마크를 병기하라.**
3. **자의적 재구성 금지**: `deep` 모드의 뼈대 재구성(5-A)은 반드시 화자의 메타발화(전환 신호)에 근거하고, 그 근거 발화를 출력에 함께 표기하라.
4. **노이즈 제거**: filler(음·어), 광고·스폰서 읽기, "구독 좋아요 알림설정" 같은 채널 운영성 발화는 제거하라.
5. **다중 화자 분리**: 영상에 2명 이상의 화자가 있으면 Core 논증(`deep` 5-B), 핵심 주장(`brief` 5-A), 화자 입장(`brief` 5-C)을 화자별로 분리 출력하라. 통합 요약 금지.
6. **정보 증발 방지**: 모드별 분기에서 빠지더라도, 화자가 한 줄이라도 던진 내용은 공통 척추(글로사리·아티팩트·무근거 주장) 중 하나에 흔적을 남겨라.
7. **가치 판단 배제**: "이 영상은 좋다/부족하다", "후크가 과장이다" 식의 AI 자체 평가는 배제하라. `deep` 5-D는 후크와 실제를 병치만 하고 판정은 연구자에게 맡겨라.
8. **모드 추천 필수**: Step 0(모드 추천)은 사용자가 모드를 명시했더라도 항상 출력하라. 사용자에게 검증 기회를 제공하기 위함이다.
9. **부연은 모드 구조를 깨지 않는 범위에서**: 사용자 부연이 모드의 핵심 섹션을 삭제하거나 다른 모드의 섹션을 끼워 넣으라는 요청이면, 그 한계를 0번 섹션 "사용자 부연 반영"에서 명시하고 가능한 범위로만 처리하라.
