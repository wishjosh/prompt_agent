# Prompt Evaluation Scorecard

> 프롬프트 평가는 형식 준수 여부가 아니라, 실제 입력에서 연구자의 판단 비용을 얼마나 낮췄는지로 본다.

## 평가 단위

평가는 "프롬프트 파일"이 아니라 "특정 입력에 대한 실행 결과" 단위로 기록한다. 한 번 좋은 결과가 나와도 프롬프트가 안정화됐다고 보지 않는다.

## 핵심 기준

| 기준 | 좋은 출력 | 실패 신호 |
|------|----------|----------|
| 목적 적합성 | 사용자가 하려던 판단에 바로 쓸 수 있는 재료를 준다 | 보기 좋지만 다음 행동이 불분명하다 |
| 원문 충실성 | 원저자의 구조, 주장, 근거, 한계를 왜곡하지 않는다 | AI가 더 매끄러운 구조로 재배열한다 |
| 근거 추적성 | 중요한 주장마다 출처, 위치, 시점이 따라온다 | 핵심 주장에 근거 위치가 없다 |
| 정보 보존 | 주변부 단서, 예외, 이상값, 한계를 완전히 증발시키지 않는다 | 일반 요약처럼 사소한 조각을 삭제한다 |
| 압축 품질 | 읽는 시간은 줄이되 판단에 필요한 해상도는 유지한다 | 지나치게 길거나, 반대로 핵심 맥락이 사라진다 |
| 불확실성 처리 | 추정, 일반 지식 보완, 검증 필요 항목을 구분한다 | 확실하지 않은 내용을 단정한다 |
| 출력 사용성 | 후속 정리, 비교, 인용, 실행으로 옮기기 쉽다 | 멋진 문장 위주라 재사용하기 어렵다 |

## 판정

- `pass`: 목적에 맞고, 큰 수정 없이 사용할 수 있다.
- `partial`: 핵심은 작동했지만 실패 신호가 명확하다. 프롬프트 수정이 필요하다.
- `fail`: 출력이 목적 판단에 거의 도움이 되지 않는다.

## 기록 형식

실행 결과 파일 상단에 HTML 주석으로 최소 기록을 남긴다.

```markdown
<!--
실사용 기록 (test record)
- 프롬프트:
- 소스:
- 실행 환경:
- 날짜:
- 판정: pass / partial / fail
- 검증 포인트:
  - ...
- 실패/한계:
  - ...
- 다음 수정:
  - ...
-->
```

## 승격 기준

- `trialed`: 실행 결과가 1개 이상 있다.
- `revised`: 실행 결과에서 발견한 한계가 프롬프트에 반영됐다.
- `validated`: 서로 다른 입력 3개 이상에서 `pass` 또는 강한 `partial`을 받았다.
- `stable`: 실제 작업에서 반복 사용되고, 실패 패턴이 예측 가능하다.
