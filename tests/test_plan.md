# 테스트 계획

현재 목표는 프롬프트를 확정하는 것이 아니라, 어떤 입력에서 어떤 실패가 반복되는지 확인하는 것이다.

## 우선 테스트

- 공통: 실행 코드블록이 5,000자 미만으로 입력 제한을 통과하는지 확인. 보고서 scan/deep은 한국어 실행 프롬프트, 그 외 프롬프트는 각 파일의 현재 실행 언어 기준을 따른다.
- 공통: 실행 결과의 일반 제목·표 라벨이 한국어로 출력되는지 확인. 단, paper scan과 report scan의 Deep 입력 블록 필드 라벨은 영어 키값으로 유지되어야 한다.
- 공통: 원문에 없는 `전략적 통찰`, `분석 결과 종합`, 정책 조언, 최종 에세이식 종합이 추가되지 않는지 확인.
- 실행 채널: 보고서 계열 scan/deep과 다중 소스 scan은 NotebookLM 일반 채팅창을 우선한다. Studio 보고서 작성은 이번 보고서 스캔 워크플로에서 사용하지 않는다.
- `collect_00_search_brief`: 서로 다른 연구 주제 2개로 소스 바구니, 가정 점검, 후속 입력값이 실제 수집에 쓸 만큼 구체적인지 확인.
- `multi_source_01_scan`: NotebookLM 일반 채팅창에서 목적 수집 소스 묶음 1개와 기록 없이 축적된 혼합 소스 묶음 1개로 소스 회계, 유형/역할 분리, 군집, 주변부 보존, 후속 처리 계획이 작동하는지 확인.
- `text_paper_01_scan`: IMRaD 학술논문 1편, 비정형 학술논문 또는 학위논문 1편. `2차 Deep 인계 블록`의 자동 작성 영역과 연구자 추가 작성 영역이 분리되는지 확인.
- `text_report_01_scan`: 연구보고서 1편, 법정 또는 비법정 계획 보고서 1편. 출력 첫 줄이 `# 1차 스캔_[소스 제목]`인지 확인한다.
- `text_report_01_scan`: 출력 구조가 `0. 소스 카드`, `1. 구조 X-ray`, `2. 심층 후보 및 연구자 선택 블록`, `3. 확인 필요 항목`으로만 구성되는지 확인한다.
- `text_report_01_scan`: `구조 X-ray`가 원문 장/절 위계를 `###`/`####`로 보존하고, 각 장에 역할·주요 내용/자료·저자 주장·대안·확인 단서 중 해당 정보가 채워지는지 확인한다.
- `text_report_01_scan`: 원문 장 제목이 최상위 또는 독립 번호 섹션으로 승격되면 실패로 본다. 원문 장/절은 반드시 `1. 구조 X-ray` 내부에만 있어야 한다.
- `text_report_01_scan`: Target scope 후보가 1개 이상 자동 제안되고, `Additional target scope` 빈 양식 1개가 포함되는지 확인한다.
- `text_report_01_scan`: 위치가 `p.8 [SOURCE_IMAGE_23]`처럼 위치 먼저·인용 마커 마지막인지 확인한다. 페이지 번호만 있고 인용 마커가 없으면 실패로 본다.
- `text_report_01_scan`: 장/절 제목과 `Scope` 뒤에 불필요한 쉼표, 대시, 빈 괄호, 남은 인용기호가 붙으면 실패로 본다.
- `text_report_01_scan`: 서로 다른 장이 하나의 `Target scope`로 묶이면 실패로 본다. 장 간 비교·연결은 `Cross-scope request`에 들어가야 한다.
- `text_paper_02_deep`: `text_paper_01_scan`의 `2차 Deep 입력 블록`을 `DEEP INPUT BLOCK` 아래에 붙이고, `0. 적용 확인`이 입력 블록의 target scope·후보 이유·사용자 추가 요청을 회수하는지 확인.
- `text_paper_02_deep`: 지정 범위 밖의 스캔 공백이나 인계 항목은 `0. 적용 확인`에만 `범위 밖`으로 표시되고 본문 분석으로 들어오지 않는지 확인.
- `text_report_02_deep`: `text_report_01_scan`의 `2. 심층 후보 및 연구자 선택 블록` 중 선택한 Target scope 1개와 관련 확인 항목만 `DEEP INPUT BLOCK` 아래에 붙이고, 분당구 일반광장 보고서 제2장·제3장·제4장 중 하나로 후보 이유·확인 필요 항목·사용자 추가 요청 회수 여부를 확인.
- `text_report_02_deep`: 지정 범위 발췌독으로 작동하는지, 전권 분석으로 확장되지 않는지, 범위 밖 확인 필요 항목이 `0. 적용 확인`에만 `범위 밖`으로 표시되고 본문 분석으로 들어오지 않는지 확인.

## 기록 위치

실행 결과는 `tests/runs/`에 저장한다. 파일 상단에 사용 프롬프트, 소스, 실행 환경, 판정, 실패/수정점을 남긴다.
