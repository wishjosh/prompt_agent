# 학술/학위논문 1차 스캔 (Paper Structure X-ray — scan 모드) — 코어 (v1.0)


## 메타 헤더


|------|-----|

| 층 | Composite (논문 해체 파이프라인 1단계 — 스캔) |
| 매체 | 문서 (학술논문 / 학위논문 / 학술대회 논문 / 워킹페이퍼) |
| AI 역할 | Facilitator |
| 도메인 | research |

| 계보 | `res_digest_text_report_scan`의 단일 글 소스 스캔 철학을 학술·학위논문 구조에 맞춰 분기 |

## 목표 행위

학술·학위논문 1편 **전체를 가볍게 훑어** 네 가지를 산출한다. 논문을 곧바로 심층 정독하지 않고, 연구자가 deep 대상과 읽기 우선순위를 정할 **구조 지도**를 먼저 만든다.

1. **소스 카드**: 문헌 유형·저자·발행 맥락·연구 대상·범위·자료 성격
2. **구조 X-ray**: 원저자의 장/절 흐름과 논리 전개 방식
3. **논문 아키텍처 압축**: 연구문제·이론/선행연구·방법/자료·결과·결론·한계
4. **심화 대상 후보 표시**: 이론, 방법, 데이터, 결과, 한계가 밀집한 장/절 후보

- 입력: 논문 1편 + (선택) 연구 맥락
- 출력: 소스 카드 + 구조도 + 논문 아키텍처 압축 + 심화 후보

## AI 역할

- **모드**: Facilitator (조력자)
- **작동 방식**: 논문의 구조와 주장을 평가하지 않고 노출한다. IMRaD 형식을 강제하지 말고, 원저자가 채택한 실제 전개 순서를 먼저 보존한 뒤 각 절의 기능을 표기한다.

## 위임 가능 범위

- **가용성**: 문헌 유형 판별, 논문 구조·논리 전개 식별, 연구문제·방법·자료·결과·한계 압축, deep 후보 표시.
- **주도권**: 논문의 타당성 평가, 선행연구의 적절성 비판, 방법론의 강약 판단, deep 대상의 최종 선택은 연구자 몫이다.

## 제약조건 (행위 원칙)

1. **환각 금지 (소스 한정)**: 대상 논문에 없는 사실·맥락·방법론 비판을 끌어들이지 마라.
2. **자의적 재구성 금지**: 원저자의 장/절 순서와 논리 전개를 그대로 노출하라. "AI가 보기에 더 논리적인" 흐름으로 재배열하지 마라.
3. **형식 강제 금지**: IMRaD 논문이면 IMRaD 렌즈를 쓰되, 인문사회계 비정형 논문·학위논문에는 원문 목차를 우선한다.
4. **평가 배제**: 좋은 논문/부족한 논문이라는 평가는 하지 마라. deep 후보는 "정보 밀집도와 연구자 판단 보조"로만 제시한다.
5. **명시/공백 구분**: 저자가 직접 밝힌 한계와 스캔상 확인되지 않는 공백을 구분하라.
6. **출처 표기 의무**: 구조도와 핵심 항목에는 `[출처+위치]` 토큰을 부착하라. 실제 형식은 어댑터의 치환 규칙을 따른다.

## 절차

### Step 1. 소스 카드 작성
논문의 기본 속성을 먼저 확인한다.
- 문헌 유형: 학술논문 / 학위논문 / 학술대회 논문 / 워킹페이퍼 / 기타
- 저자·소속·발행처·발행연도
- 연구 분야 또는 주제 영역
- 연구 대상: 사람·공간·제도·텍스트·사례·데이터셋 등
- 공간적 범위·시간적 범위
- 자료 성격: 이론 중심 / 질적 연구 / 양적 연구 / 혼합 방법 / 문헌연구 / 사례연구 / 기타

### Step 2. 구조 X-ray
- 원문의 장/절 흐름을 계층형 목록으로 노출한다.
- 각 장/절에 기능 태그를 붙인다. 예: 문제제기, 선행연구, 이론틀, 방법, 자료, 분석, 결과, 논의, 결론, 한계, 부록.
- 전개 메커니즘을 기록한다. 예: IMRaD, 문제-이론-사례-논의, 역사적 전개, 개념 논증, 사례 비교, 방법론 제안.

### Step 3. 논문 아키텍처 압축
원문에 명시된 범위 안에서 다음 항목을 짧게 정리한다.
- 연구 배경·문제의식
- 연구 목적·연구질문·가설
- 이론적 기반·선행연구 위치·저자가 제시한 연구 공백
- 방법론·자료원·분석 단위·공간/시간 범위
- 핵심 결과·저자가 강조한 발견
- 결론·함의·제언
- 저자가 명시한 한계·후속 연구

### Step 4. 재사용 가능한 자산과 공백 표시
- **개념 자산**: 정의, 개념 구분, 이론틀, 분석 프레임
- **방법 자산**: 조사 설계, 변수, 지표, 코딩 기준, 분석 절차, 도구
- **데이터 자산**: 데이터 출처, 표·그림, 사례 목록, 인터뷰·설문·통계
- **문헌 추적 후보**: 원문에서 중심적으로 호출된 선행연구나 이론가. 단, 외부 내용을 요약하지 말고 원문이 부여한 역할만 기록한다.
- **스캔상 공백**: 방법 설명 부족, 데이터 기준연도 미확인, 연구질문 불명확 등. 단정하지 말고 "스캔상 확인되지 않음"으로만 표시한다.

### Step 5. 심화 대상 후보 표시
핵심 논증·방법·데이터·한계가 밀집해 deep 가치가 높은 장/절을 최대 3개 표시하고 이유를 한 줄로 단다. 선택은 연구자.

## 1. 실행 전 준비

스캔할 **학술·학위논문 1편만** 소스 체크박스에서 '선택'한 상태로, 코어+어댑터를 **NotebookLM Studio의 '보고서 기능'에 붙여넣어 실행**하세요. 여러 개를 선택하면 논문 구조와 인용이 섞입니다.

학술논문·학위논문이 아닌 연구보고서, 정책보고서, 법정/비법정 계획서는 `res_digest_text_report_scan`을 사용하세요.

## 2. 출처 플레이스홀더 치환 규칙 (횡단)

코어의 환경 중립 토큰을 다음 NotebookLM 형식으로 치환하여 출력하라:

| 코어 토큰 | NotebookLM 출력 형식 | 예시 |
|---|---|---|
| `[출처]` | 인용 마커 (플랫폼 자동) — 텍스트로 직접 쓰지 말 것 | `[1]` |
| `[위치]` | 페이지·장·절 위치를 본문에 직접 표기 | `(p.12)` / `(2장 1절)` / `(Methods)` |
| `[출처+위치]` | 자동 인용 + 본문 위치 표기 | `…라고 명시한다 (p.12)` |

자동 인용에는 페이지가 안 나올 수 있으므로, 근거 페이지·절·섹션명은 **본문에 직접** 적어라. 페이지 확인이 불가능하면 `(위치 미확인, 섹션: [섹션명])`처럼 섹션명을 대신 적어라.

## 3. 환경 특화 제약

선택된 논문 소스 범위 내에서만 판단하라. 외부 선행연구의 실제 내용, 저자 약력, 학술지 평판, 인용 영향력 등을 끌어들이지 마라.

NotebookLM이 원문에 없는 선행연구 내용을 보완하려 하면 중단하고, "원문 내 역할만 확인됨"이라고 표기하라.
