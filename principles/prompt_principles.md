# 프롬프트 원칙

## 1. 판단을 대신하지 않는다

프롬프트의 목적은 연구자의 판단을 대체하는 것이 아니라, 판단에 필요한 구조와 근거를 빠르게 드러내는 것이다.

좋은 지시:
- 원문 구조를 노출한다.
- 핵심 근거와 위치를 남긴다.
- deep 후보를 제시하되 최종 선택은 연구자에게 둔다.

피해야 할 지시:
- 좋은 문헌인지 평가하라.
- 가장 중요한 것을 대신 선정하라.
- 원문 밖 지식으로 해석을 보완하라.

## 2. 원문 구조를 보존한다

스캔과 deep 프롬프트는 원저자의 목차, 장·절 순서, 논리 전개를 먼저 보존한다. AI가 보기 좋은 순서로 다시 쓰면 후속 검증 비용이 커진다.

## 3. 위치 추적성을 우선한다

요약이 아무리 좋아도 근거 위치가 없으면 연구 작업에서는 다시 확인해야 한다. 중요한 항목에는 인용 마커와 페이지·장·절 위치를 함께 요구한다.

## 4. 주변부를 완전히 지우지 않는다

각주, 한계, 예외 수치, 방법론의 작은 조건처럼 원저자에게는 주변부인 정보가 연구자에게는 단서가 될 수 있다. 핵심 요약에서 빠지더라도 별도 영역에 흔적을 남긴다.

## 5. 검증 전에는 단순하게 둔다

프롬프트가 안정화되기 전에는 하나의 파일로 관리한다. 코어/어댑터/빌드 분리는 반복 사용과 자동화 필요가 생긴 뒤에 도입한다.

## 6. 실패 기록이 원칙보다 먼저 움직인다

한 번의 좋은 출력보다 반복되는 실패가 더 중요하다. 테스트 결과에서 같은 문제가 반복되면 프롬프트 본문을 먼저 고치고, 원칙은 충분히 누적된 뒤에만 바꾼다.
