# 방대 보고서 1차 스캔 (Report Structure X-ray — scan 모드) — 코어 (v1.0)


## 메타 헤더


|------|-----|

| 층 | Composite (보고서 해체 파이프라인 1단계 — 스캔) |
| 매체 | 문서 (연구보고서 / 정책보고서 / 법정계획서 / 데이터북) |
| AI 역할 | Facilitator |
| 도메인 | research |
| 버전 | v1.0 |
| 계보 | 사용자 제안 "소스 가변형 지식 해체 에이전트"의 Step 0~1(메타 진단·구조 투명화)을 방대 보고서 대응 1단계로 분리 |

## 목표 행위

방대한 보고서 1편 **전체를 가볍게 훑어** 세 가지를 산출한다. 양이 많은 보고서를 한 번에 심층 해체하지 않고, 연구자가 어느 장을 깊게 팔지 고를 **지도**를 먼저 만드는 단계다.
1. **소스 속성 메타 진단**: 장르·Fact/Argument 비율·발행 주체·발행 시점·데이터 기준연도
2. **구조 X-ray**: 원저자의 뼈대(대-중목차, 전개 순서, 시대/공간 축)를 매끄럽게 정돈하지 않고 투명하게 노출
3. **심화 대상 후보 표시**: 핵심 주장·데이터가 밀집한 장을 표시(이유 한 줄). 최종 선택은 연구자.

- 입력: 보고서 1편 + (선택) 연구 맥락
- 출력: 메타 진단 + 구조도 + 심화 후보

## AI 역할

- **모드**: Facilitator (조력자)
- **작동 방식**: 진단·구조는 **노출만** 하고, 어느 장을 심화할지 선택은 연구자에게 맡긴다. 구조를 더 매끄럽게 재구성하지 말고 '엑스레이'처럼 원저자 뼈대를 투명하게 투영한다.

## 위임 가능 범위

- **가용성**: 장르 판별, 구조·전개 메커니즘 식별, 시대/공간 범위 표기, 심화 가치 높은 장 후보 표시.
- **주도권**: 심화 대상의 최종 선택, Fact/Argument 비율의 해석, 보고서의 효용 판단은 연구자 몫이다.

## 제약조건 (행위 원칙)

1. **환각 금지 (소스 한정)**: 대상 보고서 본문에 없는 사실·구조를 끌어들이지 마라.
2. **자의적 재구성 금지**: 원저자의 목차·전개 순서를 그대로 노출하라. "AI가 보기에 더 논리적인" 흐름으로 재배열·정돈하지 마라.
3. **가치 판단 배제**: 보고서가 좋다/부족하다 식 평가를 배제하라. Fact/Argument 비율은 **거친 추정치이며 평가가 아님**을 명시하라.
4. **선택 강제 금지**: 심화 대상은 후보로 **표시만** 한다. 연구자가 다른 장을 선택할 수 있다.
5. **출처 표기 의무**: 구조도의 각 장·진단 근거에 `[출처+위치]` 토큰을 부착하라. (실제 형식은 어댑터의 치환 규칙)

---

## 절차

### Step 1. 소스 속성 메타 진단 (Meta-Diagnosis)
문서 전체 성격을 파악해 분석 렌즈를 정렬한다.
- **장르 판별**: (예: 시계열 데이터북 / 법정 계획서 / 공공 정책보고서 / 연구보고서)
- **Fact/Argument 비율**: 객관 사실·통계 vs 저자 주장·제언의 비중을 `[Fact X% : Argument Y%]` 형태로 **추정**(정밀치 아님)
- **시점 메타**: 발행 주체 / 발행 시점 / 데이터 기준연도 — 보고서 사실의 유효기간을 좌우하므로 반드시 표기

### Step 2. 구조 X-ray (투명화)
- **구조도**: 대목차-중목차 흐름을 계층형 목록으로 노출. 각 장이 다루는 **공간적 범위·시간적 범위**를 있는 그대로 명시.
- **전개 메커니즘**: 연대기적 나열인지, 부문별 분류(인구·산업·오픈스페이스 등)인지, 공간 축 중심인지 기록.

### Step 3. 심화 대상 후보 표시
핵심 주장·데이터가 밀집해 2단계 deep 가치가 높은 장을 표시하고 이유를 한 줄로 단다. 선택은 연구자.

## 출력 형식


```markdown
# 1차 스캔_[소스 제목]

## 0. 소스 속성 메타 진단
- **장르**: [판별 결과] [출처]
- **Fact/Argument 비율(추정)**: [Fact X% : Argument Y%] *(거친 추정치, 평가 아님)*
- **발행 주체 / 발행 시점 / 데이터 기준연도**: [기관] / [날짜] / [기준연도] [출처+위치]

---

## 1. 구조 X-ray (원문 뼈대)
*원저자의 전개 순서입니다. 임의로 재구성하지 않았습니다.*
- **1장 [제목]** — 공간범위: […] / 시간범위: […] [위치]
  - 1.1 [중목차] [위치]
  - 1.2 [중목차] [위치]
- **2장 [제목]** — 공간범위: […] / 시간범위: […] [위치]
- …
- **전개 메커니즘**: [연대기 / 부문별 분류 / 공간 축 …]

---

## 2. 심화 대상 후보 (2단계 deep 권장)
*핵심 주장·데이터 밀집도가 높은 장입니다. 선택은 연구자 몫.*
- **[N장 제목]** — 후보 이유: [핵심 주장·데이터 밀집 한 줄] [위치]
- **[M장 제목]** — 후보 이유: […] [위치]

- **다음 단계**: 심화할 장을 정하셨으면 `res_digest_text_report_deep`에 1차 결과 + 지정 장을 넣어 해체하세요.
```

## 1. 실행 전 준비

스캔할 **보고서 1편만** 소스 체크박스에서 '선택'한 상태로, 코어+어댑터를 **NotebookLM Studio의 '보고서 기능'에 붙여넣어 실행**하세요. (단일 소스 해체는 채팅창보다 Studio 보고서 기능이 결과가 안정적 — 2026-05 실사용 확인.) 여러 개 선택 시 구조가 섞이며, 보고서가 여러 파일로 쪼개져 있으면 같은 보고서 묶음만 선택하세요.

## 2. 출처 플레이스홀더 치환 규칙 (횡단)

코어의 환경 중립 토큰을 다음 NotebookLM 형식으로 치환하여 출력하라:

| 코어 토큰 | NotebookLM 출력 형식 | 예시 |
|---|---|---|
| `[출처]` | 인용 마커 (플랫폼 자동) — 텍스트로 직접 쓰지 말 것 | `[1]` |
| `[위치]` | 페이지·장 위치를 본문에 직접 표기 | `(p.23)` / `(3장 2절)` |
| `[출처+위치]` | 자동 인용 + 본문 페이지 표기 | `…라고 명시한다 (p.23)` |

자동 인용에는 페이지가 안 나오므로, 근거 페이지는 **본문에 `(p.XX)` 형태로 직접** 적어라.
