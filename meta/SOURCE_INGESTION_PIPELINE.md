# 소스 수집 파이프라인 아키텍처

> **적용 범위**: 이 문서는 RES-002 계열 해체 프롬프트의 진입 전 단계, 즉 "어떤 소스가 어떤 경로로 처리 파이프라인에 들어오는가"를 정의한다.
> 해체 원칙 자체는 [KNOWLEDGE_SYSTEM.md](KNOWLEDGE_SYSTEM.md)에, 프롬프트 설계 원칙은 [DESIGN_PRINCIPLES.md](DESIGN_PRINCIPLES.md)에 있다.

---

## 설계의 출발점

인간 연구자가 실제로 접하는 소스는 **말, 글, 영상, 경험/목격** 네 가지가 전부다. 이 4가지는 인간의 인지적 입력 채널을 이루는 원소들이며, 이를 무시하고 곧바로 장르 분류(보고서/논문/영상 등)로 뛰어들면 파이프라인이 채널마다 다른 전처리 필요성을 놓친다.

이 관찰에서 두 층위의 아키텍처가 도출된다.

---

## 2층위 아키텍처

### Layer 1 — 인식론적 맥락 태그 (라우팅 아님)

소스가 어떤 인식론적 원천에서 왔는지를 태깅한다. **이 층위는 처리 경로를 결정하지 않는다.** 같은 TEXTUAL 소스라도 이 태그에 따라 Stage 2의 해석 렌즈가 달라진다.

| 태그 | 정의 | 예시 |
|------|------|------|
| `[DIRECT]` | 연구자 본인의 1차 감각이 원천. 암묵지(Tacit Knowledge) 영역. | 현장 답사, 주민 직접 면담, 회의 참관 |
| `[MEDIATED]` | 타인이 기호화·가공한 기록물. 형식지(Explicit Knowledge) 영역. | 보고서, 논문, 뉴스, 영상 콘텐츠 |

> **주의**: `[DIRECT]` 경험은 AI가 직접 입력받을 수 없다. 연구자가 글로 메모하거나 말로 녹음하는 순간 `[MEDIATED]`의 형태로 Layer 2에 진입한다. 따라서 `[DIRECT]`는 독립 처리 경로가 아니라, Layer 2 처리 후 해석 시 적용되는 맥락 태그다.

**`[DIRECT]` 소스의 Stage 2 해석 원칙**: 사실 추출보다 연구자의 **세렌디피티(현장에서 발생한 예상 외 발견)** 박제를 우선한다.

---

### Layer 2 — 매체 양식별 라우팅 (실제 처리 경로)

소스가 어떤 감각 채널로 들어오는지를 기준으로 실제 처리 경로를 결정한다.

```
[소스 입력]
     │
     ├─ [TEXTUAL] 글 ──────────────────────────────► 직통 → Stage 2
     │   (보고서, 논문, 법령, 기사, 메모 등)
     │
     ├─ [ACOUSTIC] 말 ─────────────────────────────► 구어 정제 → 정규화 텍스트 → Stage 2
     │   (녹취록, 인터뷰 전사본, 구술 기록)
     │
     └─ [MULTIMODAL] 영상 ─────────────────────────► res_digest_video_route → Stage 2
         (유튜브, 강연, 다큐, 현장 영상)              [음성 + 자막/시각 분리 처리]
                                                       ※ 재합산 방법 TBD
```

---

### ACOUSTIC 전처리 루틴

구어체 소스는 Stage 2 진입 전 아래 4단계를 거쳐 정규화 텍스트로 변환한다.

1. **화자 분리**: 발화자가 복수이면 A, B, C로 라벨링. 단독 화자이면 생략.
2. **구어 잡음 제거**: 필러(어, 음, 그러니까), 반복 구, 미완성 발화 삭제.
3. **구문 정규화**: 구어 어미(~잖아요, ~거든요)를 평서문으로 변환. **의미 보존, 형식만 정제.**
4. **발화 단위 → 문단 재구성**: 주제 단위로 묶어 문단 구성. 시간 순서 유지.

> **경계 판단 기준**: 텍스트 파일로 제공되더라도 내용이 구어체이면 `[ACOUSTIC]`으로 분류한다. 파일 형식이 아니라 **언어 형태**가 기준이다.

---

### MULTIMODAL 처리 현황

영상은 음성(ACOUSTIC) + 자막/시각(TEXTUAL)이 결합된 다중 매체 컨테이너다. 현재 `res_digest_video_route`가 분리 처리를 담당하지만, **분리 후 두 채널을 하나의 지식 산출물로 재합산하는 방법은 미정이다.**

- **현재**: `res_digest_video_deep/brief/recipe`가 실용적으로 운용 중
- **미결**: 음성과 시각 정보가 상충할 때의 우선순위, 재합산 출력 형식

---

## Stage 2 진입 시 전달 정보

Layer 1·2를 통과한 소스가 Stage 2(3축 스코어링 및 해체 루틴)에 진입할 때 아래 두 가지를 함께 전달한다.

```
[정규화된 텍스트]
[채널 메타데이터: DIRECT/MEDIATED + TEXTUAL/ACOUSTIC/MULTIMODAL]
```

Stage 2는 이 메타데이터를 참고해 해석 렌즈를 조정한다. 3축 스코어링([STRCT/LOOSE], [FACT/PERS], [LONG/SHRT])과 해체 루틴(A/B/C) 선택은 Stage 2의 영역이며 이 문서의 범위 밖이다.
